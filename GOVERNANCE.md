# Governance

BBPP is a **documentation-first** project. Authority is the [Charter](docs/BBPP-00-Charter.md), not a foundation vote.

## What is decided where

| Kind of change | Where | Who |
|----------------|-------|-----|
| Purpose, Non-Goals, three-force model | [Charter](docs/BBPP-00-Charter.md) | Maintainers only, after an issue |
| Defaults, measurement norms | [Guidelines](docs/BBPP-02-Best-Practice-Guidelines.md) | PR + rationale against the three forces |
| Who may contribute, review bar | [Participation](docs/BBPP-01-Participation-Standards.md) + [CONTRIBUTING](CONTRIBUTING.md) | Maintainers |
| Facts about other clients | [Landscape](docs/BBPP-Background-Client-Landscape.md) | Anyone via `landscape-update` issue |
| Adjacent maps (quantum, templates) | `research/` | Anyone; must not rewrite the Charter |
| Consensus rules | **Nowhere in this repo** | Rejected on the primary line |

Hard forks by others are welcomed. They are not this line.

## Maintainers

Public repo: [MoloBTC-Org/bbpp](https://github.com/MoloBTC-Org/bbpp).  
Stewardship sits with the MoloBTC org. There is no committee and no activation vote here.

## Visibility (GitHub About)

> Framework and future client for monetary-efficient Bitcoin nodes. Identical consensus. Policy and defaults may differ. Documentation first.

**Topics** (Settings → Topics, all lowercase):

```
bitcoin
bitcoin-protocol
full-node
bitcoin-knots
mining
proof-of-work
documentation
open-source
self-custody
sovereignty
```

Do not add ticker-style topics (`bbpp-token`, `crypto`, `nft`).

## Communication

- Issues over DMs for anything that should bind the documents.
- Landscape facts need a source link.
- “BIP assigned” is not “activated.”
- Models (including Grok) are not a substitute for the files in `docs/`.
